## Audit findings not planned (selected by user: security trio only)

Vetted and real, available for a future planning pass:

- **Scheduled crawls are a paid stub** — `CrawlSchedule` CRUD exists, no worker executes schedules (`vercel.json` has no `crons`). Product-critical.
- **Zero tests on plan limits, Stripe webhook idempotency, IDOR paths**; no CI workflow.
- **Stats computed 3× per crawl lifecycle** (`src/server.js:4650-4707` vs `4911-5070`); Excel export ignores stored `CrawlRun.stats`.
- **Project-limit check-then-act race** (`src/server.js:3267-3299`, no transaction).
- **Crawl runs in one serverless request, all pages in memory, no resume** — hard scale ceiling at 300s.
- **No lint/typecheck coverage of the 5.4k-line JS monolith**; `@types/react` 19 vs React 18 mismatch.
- **Dead weight**: `next-frontend/` orphan, `backup_neon.dump` committed at root, `scratch_styles.css`, ~18 audit MDs at root.
- **Crawl comparison + alerts** promised by plan tooltips, not implemented (direction).
- **CLAUDE.md claims a CMS module that has zero code** (direction/docs).
- **NEW (found during 001 execution): the existing test suite is not green on a clean DB** — `tests/auth.test.js` creates login users without `emailVerified: true`, so login returns 403 EMAIL_NOT_VERIFIED (`src/server.js:2771`) and 24/39 auth tests fail; `tests/stripe.test.js` webhook tests get 501 (likely missing `STRIPE_WEBHOOK_SECRET` in the dev env pull — it's Production-only in Vercel). Verified pre-existing at commit `d0d0d2a` with no working-tree changes. Small S-effort fix; should precede any plan that relies on `npm test` as a gate (e.g. 003).

- **NEW, HIGH SEVERITY (found during 004 review): every self-registered account gets the ADMIN role** — `src/server.js:2667` sets `role: USER_ROLE.ADMIN` on registration. ADMIN passes `isAdmin()`/`requireAdmin` (`lib/user-roles.js:65-66`, `src/server.js:563`), and the admin users listing (`src/server.js:~2985-3010`, `buildAdminUsersWhere` at ~825) scopes by role and owner-email exclusion but has NO team/tenant scoping — so any new signup can enumerate all non-owner users (names/emails) and, per the manageable-roles hierarchy (`src/server.js:791`), potentially manage EDITOR/USER accounts. If "ADMIN = workspace admin" is intentional, the admin queries must be scoped by `teamOwnerId`; either way this needs a dedicated plan before launch. Not fixed — advisor finding only.

- **NEW (confirmed during 003 execution): `trust proxy` is not configured on the Express app** — `grep "trust proxy" src/server.js` has no match, and express-rate-limit raised `ERR_ERL_UNEXPECTED_X_FORWARDED_FOR` when tests set that header. Behind Vercel's proxy, `req.ip` is the edge/proxy address, not the client — rate limiting may key all clients to a handful of edge IPs (over-blocking) or rotate per request (under-blocking). Small fix (`app.set("trust proxy", ...)` with the Vercel-appropriate hop count) but needs care + a test; schedule as its own small plan.
